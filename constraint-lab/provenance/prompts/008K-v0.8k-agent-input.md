# 22. Strong lumpability

Retain/standardise the exact finite definition.

A partition:

```text
Π={B_1,...,B_k}
```

```text
z,z' ∈ B_a
```

```text
sum_{u∈B_b} T(z,u)
=
sum_{u∈B_b} T(z',u).
```

This is prior-free.

It gives a first-order quotient valid for arbitrary initial distributions over Z.

# 47. Proposed taxonomy of novelty

Investigate and refine these categories:

## Process-expressive novelty

No allowed compiler reproduces the target process under the preserved representation/equivalence.

## Representation novelty

Same process can be reproduced only by adding/changing represented state.

## Semantic/modular novelty

Flattening is possible, but the new representation gives explicit structure not preserved by a flat ordinary grammar.

## Compression novelty

Equivalent process exists but requires substantially larger:

```text
state
K
J
alphabet
```

under the baseline representation.

## Observational novelty

Difference exists at one observation resolution but not another.

Do not force every result into one category if multiple apply.

# 55. Three compilation levels

That now forces a deeper formal question:

> **What exactly do we mean by “state” when we say something is new?**

A process can be:

```text
non-Markovian in X
Markovian in (X,H)
non-Markovian after projection to Y
Markovian after predictive refinement P_Y.
```

Likewise, a future dynamic constraint state η may look like a new axis while still being flattenable into a larger ordinary Markov state.

Generation 8K must therefore make explicit:

```text
which representation is being preserved
which observation is being preserved
which compiler is allowed
which notion of equivalence is required.
```

Only then is a statement such as:

```text
"H adds something genuinely new"
```

or:

```text
"L adds something genuinely new"
```

mathematically meaningful.

The goal of 8K is not another result table.

It is to establish the formal language needed to know what the **next result table would actually mean**.
