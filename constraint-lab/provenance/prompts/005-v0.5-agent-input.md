# 13. Replace the finite horizon as the primary mechanistic quantity

Add a horizon-independent eventual hit-before-return committor on the pair-event epoch process.

```text
A = full states whose pairwise graph is source class X
B = full states whose pairwise graph is target class Y

```

The event clock is the **pair-event epoch kernel**.

For a starting full state `s in A`, define:

> the probability that the process reaches `B` before it re-enters `A`, after at least one pair event.

Formally, solve the absorbing problem on the epoch kernel.

For `u in C`:

```text
h(u)
=
sum_z K_epoch(u,z) * value(z)
```

where:

```text
value(z) = 1  if z in B
value(z) = 0  if z in A
value(z) = h(z) if z in C
```

Then for `s in A`:

```text
q(s)
=
sum_z K_epoch(s,z) * value(z)
```

This is the eventual source-to-target-before-return committor.

# 15. Exploit the hidden-state block structure

The pair-event epoch calculation should not require solving a blind `1024 x 1024` hidden-event absorption problem for every kernel.

Between pair events, the pairwise state is fixed.

Only triadic relations may toggle.

At `N=4`, for a fixed pair state there are:

```text
16
```

triadic configurations.

Therefore the next-pair-event landing calculation decomposes naturally into blocks over the 64 visible pair states, with at most a `16 x 16` hidden-state transient solve per pair state.

Implement or investigate a block-structured pair-event landing solver.

It should:

- preserve the exact semantics of the current epoch kernel;
- condition on the next pair event exactly as the old solver does;
- preserve any defect/no-future-pair-event handling;
- produce the same landing kernel as the current dense solver on validation cases.

Add cross-validation tests before using it for the pair search.

This optimisation is scientifically useful because it follows the ontology:

> hidden triadic motion occurs while the visible pairwise state is fixed.

Do not change the mathematics merely for speed.
